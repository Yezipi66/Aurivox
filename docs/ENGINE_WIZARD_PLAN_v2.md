## 二、流程（⛔ Owner 定的顺序，不按手册）

⚠️ **2026-10-04 Owner 纠正**：「顺序不按手册」。
⇒ 以本节为准，`engines/_TEMPLATE/README.md` 那套顺序**作废**。

```
1. 输入 GitHub 项目链接 → 定 engines/<id>/ 的 id → 探测仓库
2. 克隆                     git clone（此时目录必须是空的）← Owner 定的：目录空的
3. 建环境                   跑名片的 install.env_command
4. 下载模型   ┐ 并发（Owner：「可以与第五步同时进行」）
5. 写名片     ┘
6. 前端能用   ← 存盘 → 平台扫目录 → 面板自动出现
```

### ⛔⛔ 为什么克隆在第 2 步、目录必须是空的

第 5 步的名片**还没写** ⇒ `engines/<id>/` 是空目录 ⇒ `git clone` 能直接用。

⚠️ 反过来做必然 fatal：
```
fatal: destination path 'engines/<id>' already exists and is not an empty directory.
```

⚠️ **【手册】第 3 步的 `init`+`fetch` 方案不适用**——
它服务于「manifest.json 已经在目录里」的情况。**本流程第 2 步时目录是空的。**

### 平台已有命令怎么进这个流程

| 步骤 | 调什么 | 说明 |
|---|---|---|
| 2 克隆 | `git clone` | ⚠️ **不调 `install-engine.cjs`** —— 它假设名片已在目录里（走 `init`+`fetch`） |
| 3 建环境 | 名片的 `install.env_command` | 照抄它的输出，⛔ 不自己实现 uv |
| 4 下模型 | 平台只**打印**名片写的命令 | 【手册:101】「平台**不替你下载**」 |
| 5 写名片 | `core/save.js` ✅ 已有 | 实测 4→5 台 |
| 6 前端 | ⛔ 什么都不做 | 【手册:133】「不需要跑任何脚本」 |

⚠️ **这一版与手册的差异有两处，都是 Owner 定的**：
① 名片从第 1 步挪到第 5 步（为了克隆时目录是空的）
② 下模型与写名片**并发**
