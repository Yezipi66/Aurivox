## 0. 一句话结论

**后端把五步的真实完成状态算对了，但前端读的字段名和后端返回的字段名对不上，
于是除了第 1 步（靠 UI 回调硬注入），其余四步在界面上永远显示「进行中」。**

`[实测]` 证据：本机起向导（`cd web && npx vite --config wizard.vite.config.mjs`），
`curl http://127.0.0.1:5199/wizard/install-state?id=cosyvoice2` 返回的 `steps_done`
键是 `prepare / env / models / manifest / verify`；而 `editor/steps.js` 的 `stepDone`
找的是 `cloned / envBuilt / weightsReady / manifestSaved / verified`。

## 1. 数据流（三处代码，全部读过）

```

      :146  weights    = weightsOnDisk(root, id)              ← checkpoints 下有文件即齐

```

## 2. 五个键的错位（逐个列出）

| 步骤 | `stepDone` 读的键（steps.js） | 后端返回的键（installState.js） | 现状 |
|---|---|---|---|
| 1 prepare | `facts.cloned` | `prepare` | ❌ 端点路径 miss；**仅** `App.jsx:120` 的 `addFacts({cloned:true})` 能救 |
| 2 env | `facts.envBuilt` | `env` | ❌ 永远 miss |
| 3 models | `facts.weightsReady` | `models` | ❌ 永远 miss |
| 4 manifest | `facts.manifestSaved` | `manifest` | ❌ 永远 miss；仅 `App.jsx:121` 的 `addFacts({manifestSaved:true})` 能救 |
| 5 verify | `facts.verified` | `verify` | ❌ 永远 miss，且 `:150` 硬编码 false |

**用户可见后果**：装完依赖、下完模型、存好名片，流程条上第 2-5 步旁边仍是「进行中」。

## 3. 改动范围

### 3.1 必做：把判据键与后端返回对齐

| | |
|---|---|
| **scope** | `steps.js` 的 `stepDone` 改读 `prepare / env / models / manifest / verify` 五个键（与 `installState.js:152-164` 的 `steps` 键逐字相同）；`App.jsx` 的 `addFacts` 两处硬注入（`:120` `cloned`、`:223` `manifestSaved`）改成用同一套键，删掉「注入一个后端不算的假完成」这条岔路 |
| **文件** | `tools/engine-wizard/editor/steps.js` · `tools/engine-wizard/editor/App.jsx` · 各自的测试（`test/steps.node.test.js` 若断言了旧键名，同步改） |
| **预期效果** | 五个步骤的亮勾与否完全由 `installState` 的真实产物判定，不再有「点了按钮就亮」的假完成 |
| **验收点** | ① `node --test tools/engine-wizard/test/steps.node.test.js` 全绿<br>② 起服务后 `curl /wizard/install-state?id=<已装引擎>` 的 `steps_done` 与界面徽章逐项一致<br>③ 变异：把 `steps.js` 里任一键名改回错的 ⇒ 对应测试必须变红 |
