# 文案语气规范（本轮统一口径）

> 适用：**用户可见文案**（`t('en','中文')` 中文位、JSX 可见文本、`zh:`/`error:`/`note:`/`why:`/`hint:`/`label:`/`title:`/`caveat:`/`message:`、后端返回给前端的消息、CLI 打印）。
> ⛔ 不适用：代码注释、测试、变量名。

## 两条总原则

1. **正式、严谨、规范** —— 用户看到的每一句都应是软件该说的话，不是人在聊天。
2. **规范严谨优先于简短** —— 短标签（徽章/按钮）也可以写全，不要为省字牺牲规范。

## ⛔ 符号：全部保留，只改文字

`⛔` / `⭐` / `✅` / `⚠` / `★` 一律**保留原位**（它们是产品符号）。
本轮**只改符号后面的文字**，不许删符号、不许改符号。

## ⛔ 机械替换的陷阱（实测踩过，必须知道）

**批量替换会产生「守卫查不到的病句」。** 本仓库实测过三类：

| 陷阱 | 实例 | 为什么守卫查不到 |
|---|---|---|
| **替换后接不上** | `只在作者那台机器上成立` → 机械替换 `那台机器→该机器` → `只在作者**该机器**上成立` | 禁词表里只有 `这台机器`，`该机器` 是替换**结果**，不在表里 |
| **装饰线被打成乱码** | 注释里整行 `——————` 被破折号规则逐字符换成 `：：：：…，` | 规则只判「是不是破折号」，不判「是不是装饰线」 |
| **误删有意义的引用** | `契约 §8:590「参数表只有一份」` 被当变更编号删掉 | 规则只认 `刀 X1`/`Patch #N` 等模式，`§N:M` 不在模式里 |

**三条硬规矩：**

1. **替换词要带上下文，不能只换词。** `那台机器` 前面有「的/着」等定语时，`该` 接不上 ⇒ 改前先看整句。
2. **装饰线（整行 `——`）单独处理**，不参与破折号规则。改用 `# ------` 或 `===`。
3. **`契约 §N:M` / `§N.N` 是现行规范引用，保留**；只有「刀/ Patch / 日期 / 这一刀 / 过去这里是」才是变更历史。

**验收方法（守卫之外必须做的）：**

- **逐句读改动**（机械替换后句子通顺与否，只有人能判断）
- **注释/字符串感知的分词器对比**：把文件拆成「代码骨架」与「字符串列表」，逐文件对比改动前后 ⇒ 能发现「代码被误改」和「字符串被改坏」
- **对比原文**：`git diff` 逐行读，确认没删掉技术内容

## 改法自检（每条改完问自己）

1. 这句话像一个软件说的，还是像人在聊天？
2. 把这句话给一个不认识这个项目的人看，他能准确理解吗？
3. 有没有把我们的内部设计原则讲给用户听？
4. 符号（⛔/⭐/✅/⚠/★）还在原位吗？
5. **替换后整句读得通吗**（机械替换最容易在这里翻车）
6. **删掉的是不是变更历史**（`契约 §N:M` 这类规范引用不能删）
7. **装饰线有没有被打成乱码**（整行 `——` 要单独处理）

## 配色语义（界面提示条与按钮）

> 适用：**用户可见的提示条与按钮**（`.msg-*`、`.btn-*`、`.badge-*`）。这是开发规范，不做成守卫测试。

### 三档语义

| 颜色 | 语义 | 项目类 | 用在什么上 |
|---|---|---|---|
| 蓝 | **陈述** | `.msg-info` | 客观说明现状或这一步会发生什么，不含风险判断 |
| 黄 | **警告** | `.msg-warn` | 低风险但需要注意：耗时、量大、填错不报错、配置缺失 |
| 红 | **危险** | `.msg-danger` / `.msg-error` | 不可撤回，或终止一个已经开始的操作；以及一切错误 |

### 判据

1. **陈述就是陈述。** 「本操作会将 X 克隆到 Y」只说明会发生什么，不含风险判断 ⇒ 蓝色。带「将」「会」这样的将来式，不代表它就是警告。
2. **警告留给「低风险但有代价」的事。** 下载数 GB、耗时较长、某个可选模型缺失、填错不会报错 ⇒ 黄色。
3. **危险留给两件事**：
   - **不可撤回**（删除、覆盖、永久删除）⇒ 红色提示条 + 红色按钮。
   - **终止一个已经开始的操作**（取消克隆、取消安装、取消合成、取消转写）⇒ 红色按钮。
4. **Error 一律红色。** `.msg-error` 与 `.msg-danger` 同为红色，只是历史上两个类名并存。加载失败、检查失败、解析失败这类「出错了」不许画成蓝色。
5. **纯中性的操作按钮用默认色**（`.btn` 灰色、`.btn-ghost`）。不要因为「取消」两个字就上红色：**关掉一个弹窗、退出恢复横幅、放弃一次编辑**都不危险，它们不终止任何已开始的事。
6. **同一处的等级要一致。** 一条提示条里若同时有陈述与危险，分开写：陈述一条蓝色，危险一条红色，不要混成一条。

### 反例（本仓库实测改过的）

| 原来 | 改成 | 为什么 |
|---|---|---|
| 克隆提示条 `.msg-warn` | `.msg-info` | 只陈述「会克隆到哪」，没有风险判断 |
| 「目标目录已存在且不为空」`.msg-warn` | `.msg-danger` | 配套的「清除该目录」按钮删掉全部内容，不可撤回 |
| 「删除 recipe？此操作无法撤销」`.msg-warn` | `.msg-danger` | 不可撤回 |
| 「已存在同名 recipe，是否覆盖」`.msg-warn` | `.msg-danger` | 覆盖掉原内容不可取回 |
| 「校验加载失败」`.msg-info` | `.msg-danger` | 出错了 |
| 安装步骤的「取消」`.btn` | `.btn-danger` | 终止一个已经开始的安装，环境会停在不完整状态 |
| 合成/转写步骤的「取消」`.btn` / `.btn-ghost` | `.btn-danger` | 终止一个已经开始的操作 |
